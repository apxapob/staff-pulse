# ADR 002. Индекс и инкрементальная агрегация

Статус: принято.

## Контекст

Таблица показывает сумму численности и бюджета, а также взвешенную эффективность для каждого поддерева. При изменении метрики листа меняются его показатели и показатели предков; другие ветви сохраняют значения. Состояние раскрытия, выбор и сортировка должны переживать обновления данных.

## Решение

Проверенный плоский массив преобразуется в индекс с картами узлов и детей, глубинами и порядком «дети перед родителями». Первый расчёт проходит по каждому узлу и ребру один раз: `O(n)` времени и памяти. Показатели собственного узла прибавляются к результатам его непосредственных детей. Для эффективности первоначальный проход хранит числитель `Σ performance × headcount`, чтобы не усреднять уже усреднённые проценты.

Пакет метрик сначала полностью валидируется. Затем заменяются только действительно изменившиеся исходные записи. Для каждой такой записи собирается путь к корню; общие участки путей объединяются. Затронутые узлы обрабатываются по убыванию глубины, чтобы родитель использовал уже обновлённый результат ребёнка.

Пересчитываются только зависимые числовые поля: бюджет влияет на бюджет, эффективность — на её взвешенный числитель, численность — на сумму сотрудников и среднюю эффективность. Обновление эффективности узла без сотрудников не меняет агрегаты. Если изменения детей взаимно компенсируются, неизменившийся агрегат предка сохраняет прежний объект.

## Стоимость и разделение данных

Пусть `n` — число узлов, `a` — число затронутых узлов вместе с предками, `c` — суммарное число их непосредственных детей. Числовой пересчёт занимает `O(a log a + c)`: затронутые узлы сортируются по глубине и читают готовые агрегаты детей. Посторонние поддеревья не обходятся.

Для неизменяемого обновления стандартные `Map` копируются поверхностно. Такая копия требует `O(n)` времени и памяти ссылок; поэтому весь пакет нельзя называть операцией строго `O(a)`. Сами неизменившиеся `OrgNode` и `OrgAggregate` остаются прежними объектами, а структурные карты вообще не копируются. Полностью идентичное обновление возвращает исходные индекс и карту агрегатов.

Списки сотрудников не прибавляются к агрегатам отдельно: их длина уже отражена в собственной численности узла. Пакет со списками дополнительно проверяет уникальность ID сотрудников в конечном снимке за `O(e)`, где `e` — общее число сотрудников. Изменение только имени, должности или состава при прежней численности сохраняет карту агрегатов.

Инкрементальный расчёт восстанавливает взвешенный вклад ребёнка как `child.performance × child.headcount`. Из-за арифметики IEEE-754 возможны малые отличия от первоначального прохода. Тесты сравнивают численность точно, дробные показатели — с допуском; округление для интерфейса выполняется отдельно. При нулевой общей численности результат эффективности — `null`.

## Проверка решения

Доменные тесты сравнивают последовательность детерминированных случайных пакетов с полным пересчётом. Отдельно проверяются сохранение ссылок соседних ветвей, одновременное изменение предка и потомка, порядок пакета, нулевая численность, компенсация изменений и отсутствие частичной записи при ошибке. Проверки глубокой цепочки подтверждают, что доменные обходы не зависят от рекурсивного стека.

Полный пересчёт проще, но заменял бы все агрегаты при каждом событии. Поддержка только дельт числителя и сумм уменьшила бы чтение детей, но усложнила бы согласование пакетов и потребовала отдельного состояния. Для текущего объёма данных выбран пересчёт затронутых предков по уже готовым детям.
